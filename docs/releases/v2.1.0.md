# v2.1.0 — GitLab CLI, Azure CLI, Muse Code, OpenCode and Pi

## Highlights

- **GitLab CLI**: a new Version control choice. It installs `glab` 1.128.0
  from the pinned official GitLab release archives. Run `glab auth login` to
  sign in.
- **Azure CLI**: a new Cloud choice. It installs `az` 2.92.0 from the pinned
  official archives. On macOS and Linux, it runs from bytecode with its own
  pinned Python 3.14.8, and Update changes both together. Run `az login` to
  sign in. Extensions that you add with `az extension add` stay in
  `~/.azure`.
- **Muse Code CLI**: a new AI coding choice. It installs Meta's pinned `muse`
  1.4.14-R7309.1 binary. Setup does not run Meta's install script and does not install its
  self-updating launcher. Run `muse login` once, and then turn on the Muse
  provider in T3 Code.
- **OpenCode CLI**: a new AI coding choice. It installs the pinned `opencode`
  2.2.5 binary from its official GitHub release. On amd64 it uses the builds
  that do not need AVX2. The managed shell sets `OPENCODE_DISABLE_AUTOUPDATE=1`
  while OpenCode is selected. Sentinel counts OpenCode as a host when the same
  selection installs it. Run `opencode service stop` before Update or removal.
- **Pi coding agent**: a new AI coding choice. It installs the pinned `pi`
  1.5.0 release build. Setup writes nothing to `~/.pi`. Sign in with `/login`
  inside `pi`.
- **gh**: the Git credential helper that `gh auth login` or `gh auth setup-git`
  writes now survives a gh Update on macOS and Linux. The managed shell sets
  `GH_PATH` to the stable `current/bin/gh` link. A helper line that an earlier
  gh wrote stays unchanged. To correct it, open a new terminal after Update,
  and then run `gh auth setup-git` again.
- On Windows Terminal, the PowerShell prompt no longer flickers when you press
  Tab. The cursor now shows the vi mode: a block in command mode and an
  underline in insert mode.

Setup does not sign you in to GitLab, Azure, Muse, OpenCode or Pi, and it
writes no credentials.

## Compatibility and upgrade

The supported platforms do not change: Apple Silicon macOS, Ubuntu and Debian
on amd64 or arm64, and native Windows amd64. WSL uses the Ubuntu and Debian
items. The steps are the same on each platform. Use `setup.sh` on macOS and
Linux, and `setup.ps1` on Windows.

This release reads the same installer states as v2.0.0: the states of v1.2.0
and later.

To move from v1.2.0 or v2.0.0:

1. With the checkout that you have, finish or abandon each interrupted
   operation.
2. Update the checkout to `v2.1.0`.
3. Open setup and choose **Update tools**. Run **Check**, and fix each problem
   that it reports.

To move from an older release, update to `v1.2.0` first. Follow
[From a release before v1.2.0](../UPGRADING.md#from-a-release-before-v120).

The new choices passed the native archive and agent lifecycles of their pull
request on the hosted macOS, Linux amd64 and arm64, and Windows runners. An
update of an installed machine from v2.0.0 to this release is not tested.
