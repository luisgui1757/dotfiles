# v1.2.0 — T3 Code app, the latest Sentinel release and security pin updates

## Highlights

- T3 Code app. The **T3 Code** selection installs the desktop app, which has
  its own server:
  - macOS 13 or later: Homebrew installs the official `t3-code` cask, and T3
    updates itself.
  - Ubuntu and Debian: setup unpacks the official v0.1.6 `.deb` privately. A
    start script disables T3's own updater, so **Update tools** moves the app.
    The app runs without Chromium's sandbox, because Ubuntu restricts the user
    namespaces that the sandbox needs.
  - Windows: install the app yourself with `winget install T3Tools.T3Code`.
  - The earlier selection is now **T3 Code server**. A saved selection keeps
    the server and does not add the app. Only one T3 server can use a T3 home
    at a time.
- Sentinel. **Update tools** installs the latest published, immutable Sentinel
  release, so a new Sentinel release no longer needs a dotfiles change. When
  GitHub cannot report that release, setup does three things. It keeps an
  installed release of v0.3.0 or later, installs v0.3.0 over an older one, and
  stops a first install. Setup also installs the `formal` and `ops` skill profiles. A
  Sentinel install older than v0.3.0 gets a repair instead of a stop.
- Security fixes in the pins:
  - fzf 0.74.5 fixes GHSA-w6x2-f5m4-xw82 (high).
  - jq 1.8.2 fixes three high advisories, for example GHSA-cfh2-vwfq-qfmm.
  - VS Code 1.144.1 on macOS and Windows, and 1.141.2 on Linux, have the
    1.141.1 security fixes. These include one critical workspace trust bypass and
    seven high advisories, four of them remote code execution.
  - Node 24.22.2 includes the 24.22.1 security release.
- Other pin updates: T3 Code server 0.1.6, gh 2.103.3, PowerShell 7.6.9,
  Claude Code 2.1.311, Codex CLI 0.166.0, Copilot CLI 1.0.105, Kiro CLI
  2.37.1, Atuin, CMake, fd, gh-dash, Herdr, lazygit, Obsidian portable,
  ripgrep and xremap.
- The weekly pin workflow proposes verified updates for 28 resources in one
  pull request. A person merges it. The Renovate dashboard lists new releases
  of the other pins too, except Build Tools, the VC runtime and the Neovim
  plugin lock.
- A machine that v1.0.0 installed, with or without a v1.0.1 update, stopped on
  v1.1.0. It now updates directly.

## Compatibility and upgrade

The supported platforms do not change: Apple Silicon macOS, Ubuntu and Debian
on amd64 or arm64, and native Windows amd64. WSL uses the Ubuntu and Debian
items. The steps are the same on each platform. Use `setup.sh` on macOS and
Linux, and `setup.ps1` on Windows.

Before you update:

- Stop T3 Code if it runs. This release moves the T3 Code server from 0.1.0 to
  0.1.6.
- On a machine that v1.0.0 installed, the Sentinel handover drops the saved
  original of an adopted rules block. A later removal cannot restore it. Text
  outside the block stays. See
  [Sentinel rules and skills](https://github.com/luisgui1757/dotfiles/blob/v1.2.0/docs/UPGRADING.md#sentinel-rules-and-skills).

To move from v1.0.0, v1.0.1 or v1.1.0:

1. With the checkout that you have, finish or abandon each interrupted
   operation.
2. Update the checkout to `v1.2.0`.
3. Open setup and choose **Update tools**.
4. Run **Check**, and fix each problem that it reports.
5. Optional: run **Choose tools** with the same selection. It releases the old
   Sentinel records. A machine that v1.0.0 installed can need two runs.

On Linux, updates from v1.0.0, v1.0.1 and v1.1.0 with about 20 selections each
ended with Check ready. The macOS and Windows updates are not tested.

To move from v0.4.x:

1. Check out `v1.0.1` and run `./migrate.sh` or `.\migrate.ps1`. Finish all
   phases.
2. Update the checkout to `v1.2.0`. Open setup and choose **Update tools**.

To add the T3 Code app on macOS or Linux, choose **Choose tools** and select
**T3 Code**. On Windows, use `winget`.
