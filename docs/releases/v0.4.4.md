# v0.4.4 — Automated releases and current agent tooling

> Release candidate notes. Publish these only with the official annotated
> `v0.4.4` tag after the deterministic evidence gate below passes.

## Highlights

- Releases now use one manifest-bound prepare, certify, publish, recovery, and
  closure state machine. It proves the reviewed and merged trees are identical,
  revalidates required CI, scans the release range, verifies exact-tag hosted
  evidence and a credential-free public clone, then crosses one explicit
  immutable-publication boundary.
- POSIX and PowerShell migrations now share ordered legacy-release registries,
  removing duplicated version-specific recovery scans while preserving exact
  frozen-source rollback authority.
- Herdr moves to stable v0.7.5 on POSIX and the matching current Windows
  preview. This brings the upstream agent-automation facade, reusable views,
  startup hooks, sidebar controls, and accumulated multiplexer fixes while
  retaining the managed Rose Pine and tmux-shaped configuration.
- Pi CLI moves to 0.82.1 with byte-verified npm packaging and exact same-release
  companion modules. Chezmoi moves to 2.71.1; pylatexenc moves to 2.11 through
  its explicitly selected, hash-verified source distribution. The Homebrew and
  cargo-binstall bootstrap commits, Renovate validator, and checkout Action
  digest are refreshed to reviewed immutable identities.

## Compatibility and upgrade

This is a backward-compatible patch release. It changes no managed target
location or persisted dotfiles schema. Herdr 0.7.5 makes plugins global to the
user instead of session-local; this repository does not install Herdr plugins,
but anyone who manually installed one only inside an older named session should
install or link it once in the new global registry.

Do not update an older checkout in place. Clone the exact annotated `v0.4.4`
tag beside the checkout that currently owns live config, then run:

```bash
./setup.sh --all
```

```powershell
.\setup.ps1 -All
```

Existing v0.2.0 through v0.4.3 installations use ordinary setup reconciliation
from the new checkout. The same entrypoints retain the frozen-source direct
v0.1.0 migration transaction. Keep the prior checkout and any printed recovery
directory until setup completes and the applications you use have been checked.

## Release identity

The published release accepts only the exact local annotated `v0.4.4` tag
object, peeled commit, clean HEAD, and matching official-remote identities. The
explicit POSIX `--allow-unreleased` field-test lane can accept a clean current
official branch head before publication; it is not migration authority.

## Evidence required before publication

- The full local gate and every required hosted PR check must pass on the exact
  reviewed tree, with the preparation PR's reviewed and squash-merged trees
  proven identical.
- Gitleaks must find no secrets in the complete prior-release range or the
  downloaded proof tree.
- A new cache-free exact-tag run must pass all four producers and all four
  stable logical proof jobs, with every proof marker bound to the expected SHA,
  run, attempt, and context.
- A credential-free detached public clone must reproduce the tag identities,
  release-upgrade gate, and prerequisite-helper identity path.
- The GitHub release, uploaded certification proof, immutable flag, latest flag,
  draft state, and prerelease state must all read back exactly before closure.
- Real WSL, redirected-Windows known folders, divergent Windows Terminal state,
  physical Linux, Apple-Silicon owner-host lifecycle, and visual/manual rows
  remain explicit residual evidence gaps unless separately executed and
  recorded; publication must not imply that they passed.
