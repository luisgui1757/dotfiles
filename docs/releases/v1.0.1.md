# v1.0.1 — Native interactive installer replaces Nix and chezmoi

> Published on 2026-10-29 as immutable/latest GitHub release
> [`427470846`](https://github.com/luisgui1757/dotfiles/releases/tag/v1.0.1).
> Annotated tag object `ec8f89db3a91a2a0ec7077f0c07d317d075bedb7` peels to commit `bf38b04ec0d1be9e9fa969aabf527ac42f38ed51`.

## Highlights

v1.0.1 is the first published release of the native installer. It replaces
v1.0.0. The v1.0.0 tag exists, but its certification runs failed each macOS
Node download on degraded hosted networks. For that reason, v1.0.0 has no
release.

- One interactive installer replaces Nix, nix-darwin, Home Manager and chezmoi
  on each platform. `./setup.sh` (or `.\setup.ps1`) opens a menu with four
  items: Choose tools, Update tools, Check installation and Exit.
- You select tools by category. Setup adds the dependencies that each tool
  needs. One confirmation screen shows each change before setup makes it. When
  you clear a tool, setup removes it.
- Setup records the items that it owns. Update and removal change only these
  items.
- Setup adopts an existing configuration only after you approve it. It keeps
  the original and puts it back when you remove the tool.
- If an operation stops, a recovery journal keeps its state. The menu then
  continues the operation. Each run writes a log next to the installer state.
- Tools come from upstream archives with pinned checksums. Setup installs them
  in a private folder for each user. One native provider installs the system
  packages: APT on Ubuntu and Debian, Homebrew on macOS, and verified vendor
  installers on Windows.
- Update installs the reviewed versions that the checkout pins. It does not
  download a newer version that nobody reviewed.
- Archive downloads continue a slow or reset transfer with HTTP byte ranges.
  One 15-minute limit applies to the full transfer. The final SHA-256 check
  does not change.
- You can select these tools:
  - Editors: Neovim (with locked plugins, parsers and language tools) and VS
    Code.
  - Shell essentials: zsh on macOS and Linux, PowerShell 7 on Windows, zsh from
    bash terminals, Starship, lsd, zoxide, fzf, ripgrep and fd.
  - Version control: Git, lazygit, GitHub CLI and gh-dash.
  - Terminal apps: Ghostty and Windows Terminal.
  - Terminal sessions: tmux and Herdr.
  - AI coding: T3 Code, Claude Code, Codex, GitHub Copilot CLI, Kiro CLI (macOS
    and Linux), and Sentinel rules and skills.
  - Desktop apps: OpenWhispr, Obsidian, Tailscale, Zen Browser, AeroSpace, and
    Mac keyboard shortcuts on Linux.
- Setup does not offer Pi or WezTerm.
- Sentinel rules and skills runs the Sentinel installer at a pinned commit. It
  runs it for each agent CLI that it finds: Claude Code, Codex, Copilot, Kiro
  and OpenCode. Before each run, setup verifies each file of the pinned
  checkout.
- When you select Neovim, it becomes the shell editor on macOS and Linux. This
  includes `sudo -e`.
- Some accounts cannot change their login shell, for example company directory
  accounts. For these accounts, the "zsh from bash terminals" item opens zsh in
  each bash terminal.
- Agent CLI versions stay pinned. Each week, a workflow proposes verified
  version updates as pull requests.
- `./migrate.sh` and `.\migrate.ps1` move a v0.4.x installation to the new
  installer. They do these steps:
  1. Detach the released shell profiles and keep recovery copies.
  2. On macOS, convert the Homebrew installation that Nix manages.
  3. Open the new menu.
  4. Show a preview of the removal of the verified old runtimes and tools.

## Compatibility and upgrade

This major release breaks compatibility. It has no mode that keeps the old
runtime.

The release supports Apple Silicon macOS, Ubuntu and Debian on amd64 or arm64,
and native Windows amd64. WSL uses the Ubuntu and Debian items. The release does
not support Intel Macs or programs that run through Rosetta. The hosted native
tests use Ubuntu 26.04 and Debian 13. Older distribution releases have no
certification.

To move from v0.4.x:

1. Save the local changes in your checkout.
2. Update the checkout that you keep, or clone `v1.0.1` next to it.
3. Run `./migrate.sh` or `.\migrate.ps1`. Follow
   [the migration guide](https://github.com/luisgui1757/dotfiles/blob/v1.0.1/docs/UPGRADING.md).
4. Keep the recovery paths that migration shows. Keep them until you check your
   shell and your applications.

To move from v1.0.0 or from an earlier native-installer revision:

1. With the checkout that you have, finish or abandon each interrupted
   operation.
2. Update the checkout.
3. Open setup and choose Update tools.

The first apply moves the Sentinel skill copies of v1.0.0 to the Sentinel
installer. Before you do it, read
[Sentinel rules and skills](https://github.com/luisgui1757/dotfiles/blob/v1.0.1/docs/UPGRADING.md#sentinel-rules-and-skills).

For a new installation, clone the repository to a permanent location. Run
`./setup.sh` or `.\setup.ps1` as a normal user. Setup asks for administrator
access only for the changes that you approve. The managed configuration points
to the checkout, so do not move or delete the checkout.

## Release identity

The release is the annotated `v1.0.1` tag on the official repository. The tag
points to the merged release commit. Publication verifies the tag and the
commit before the release exists. The `v1.0.0` tag does not change, and it has
no GitHub release.

The setup and migrate entry points do not check tags. They verify the pinned Go
toolchain archive, then build the installer from the checkout that you have.
Update applies the versions that this checkout pins.
