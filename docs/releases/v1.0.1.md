# v1.0.1 — Native interactive installer replaces Nix and chezmoi

> Release candidate notes. Publish these only with the official annotated
> `v1.0.1` tag after the deterministic evidence gate below passes.

## Highlights

v1.0.1 is the first published release of the native installer. It replaces
v1.0.0, which was tagged but never published: its certification runs failed
every macOS Node download on degraded hosted networking.

- One interactive installer replaces Nix, nix-darwin, Home Manager and chezmoi
  on every platform. `./setup.sh` (or `.\setup.ps1`) opens a menu: Choose tools,
  Update tools, Check installation and Exit. Tools are ticked by category,
  required dependencies are added automatically, and one confirmation screen
  shows every change before anything runs. Unticking a tool removes it.
- Setup records what it owns, and update and removal touch only that. Existing
  configuration is adopted only with your approval; its original is kept and
  restored on removal. Interrupted work keeps a recovery journal and resumes
  from the menu. Each run writes a log beside the installer state.
- Tools come from checksum-pinned upstream archives installed privately per
  user, with one native provider for system packages: APT on Ubuntu and Debian,
  Homebrew on macOS and verified vendor installers on Windows. Update applies
  the checkout's reviewed versions; it never fetches arbitrary latest releases.
- Archive downloads resume a slow or reset transfer with HTTP byte ranges,
  inside one 15-minute limit for the whole transfer. The final SHA-256 check is
  unchanged.
- Selectable tools: Neovim (locked plugins, parsers and language tools), VS
  Code, zsh, PowerShell 7, Starship, lsd, zoxide, fzf, ripgrep, fd, Git,
  lazygit, GitHub CLI, gh-dash, Ghostty, Windows Terminal, tmux, Herdr, T3 Code,
  Claude Code, Codex, GitHub Copilot CLI, Kiro CLI (macOS and Linux), Sentinel
  rules and skills, OpenWhispr, Obsidian, Tailscale, Zen Browser, AeroSpace,
  and Mac keyboard shortcuts on Linux. Pi and WezTerm are retired.
- Sentinel rules and skills runs Sentinel's own installer at a pinned commit
  for each agent CLI it finds: Claude Code, Codex, Copilot, Kiro and OpenCode.
  Setup verifies each file of the pinned checkout before it runs the installer.
- Selected Neovim is the shell editor on macOS and Linux, including for
  `sudo -e`. The optional "zsh from bash terminals" choice gives accounts whose
  login shell cannot be changed, such as company directory accounts, a zsh
  terminal.
- Agent CLI versions stay pinned; a weekly workflow proposes verified version
  bumps as pull requests.
- `./migrate.sh` and `.\migrate.ps1` move an existing v0.4.x installation: they
  detach the released shell profiles with recovery copies, convert Nix-managed
  Homebrew on macOS, open the new menu and then preview removal of the verified
  old runtimes and tools.

## Compatibility and upgrade

This is a breaking major release with no old-runtime compatibility mode.
Supported platforms are Apple Silicon macOS, Ubuntu and Debian on amd64 or
arm64, and native Windows amd64. WSL uses the Ubuntu and Debian choices. Intel
Macs and Rosetta execution are not supported. Hosted native acceptance targets
Ubuntu 26.04 and Debian 13; older distribution releases are not certified.

Coming from v0.4.x: save local checkout changes, update the checkout you keep
(or clone `v1.0.1` beside it), then run `./migrate.sh` or `.\migrate.ps1` and
follow
[the migration guide](https://github.com/luisgui1757/dotfiles/blob/v1.0.1/docs/UPGRADING.md).
Keep the printed recovery paths until you have checked your shell and
applications.

Coming from v1.0.0 or an earlier native-installer revision: first finish or
abandon any interrupted operation with the checkout you have. Then update the
checkout, open setup and choose Update tools. The first apply hands over the
Sentinel skill copies of v1.0.0; read
[Sentinel rules and skills](https://github.com/luisgui1757/dotfiles/blob/v1.0.1/docs/UPGRADING.md#sentinel-rules-and-skills)
before it.

New installs clone the repository to a lasting location and run `./setup.sh` or
`.\setup.ps1` as an ordinary user. Setup asks for administrator access only for
approved changes. Managed configuration points back to the checkout, so keep it
in place.

## Release identity

The release is the annotated `v1.0.1` tag on the official repository, peeling
to the merged release commit; publication verifies both before the release
exists. The `v1.0.0` tag stays unchanged and unpublished. The setup and migrate
entrypoints do not check tags: they build the installer from the checkout you
have, after verifying the pinned Go toolchain archive, and Update applies that
checkout's pinned versions.

## Evidence required before publication

- Full local gate (`make ci`) on the release tree, and every required hosted
  check on the merged commit.
- A first-attempt `installer-engine.yml` run on the exact tag with every
  manifest-bound native job successful, archived run and job records, a redacted
  Gitleaks scan of `v0.4.4..v1.0.1`, and a fresh credential-free public clone
  reproducing the tag.
- Immutable, latest, non-draft release readback with the certification asset.

Field evidence, not certification: on 2026-10-28 the owner's Ubuntu 26.04
amd64 host migrated from v0.4.x with main at `bbbef4d` (PR #103), and Check
installation then passed. The owner's corporate Ubuntu 24.04 laptop, corporate
Windows laptop and Apple Silicon MacBook Air run pre-release revisions and did
not run the release commit before tagging. Actual reboots, first-time
permission grants, real WSL, redirected-Windows and visual checks remain manual
residual evidence.
