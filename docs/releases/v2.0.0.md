# v2.0.0 — Setup reads only the states of v1.2.0 and later

## Highlights

- Setup reads the installer states that v1.2.0 and later leave on a machine.
  An older machine updates to v1.2.0 first. v1.2.0 is the oldest release that
  updates directly to this one.
- Setup no longer hands the Sentinel files that dotfiles 1.0 copied to the
  Sentinel installer. v1.2.0 does that handover. After it, **Update tools**
  keeps the old records, and a later **Choose tools** run releases them.
- Setup no longer reads the states that only unreleased builds wrote:
  - the whole-file Git and VS Code settings and their restoration
  - the private Obsidian Flatpak on Linux and the private Zen bundle on macOS
  - revision-0 disk images and revision-0 Windows Python preparations
  - the old VS Code Linux fingerprint
- When setup finds a record that only v1.2.0 can finish, it stops before any
  change. The message names the resource and the v1.2.0 step. A record that
  setup no longer owns goes away, and its files stay.

## Compatibility and upgrade

The supported platforms do not change: Apple Silicon macOS, Ubuntu and Debian
on amd64 or arm64, and native Windows amd64. WSL uses the Ubuntu and Debian
items. The steps are the same on each platform. Use `setup.sh` on macOS and
Linux, and `setup.ps1` on Windows.

To move from v1.2.0:

1. With the checkout that you have, finish or abandon each interrupted
   operation.
2. Update the checkout to `v2.0.0`.
3. Open setup and choose **Update tools**. Run **Check**, and fix each problem
   that it reports.

To move from v1.0.0, v1.0.1 or v1.1.0:

1. Update the checkout to `v1.2.0`. Open setup and choose **Update tools**.
   Run **Check**, and fix each problem that it reports.
2. Continue with the steps for v1.2.0.

To move from v0.4.x:

1. Check out `v1.0.1` and run `./migrate.sh` or `.\migrate.ps1`. Finish all
   phases.
2. Continue with the steps for v1.0.0, v1.0.1 or v1.1.0.

On Linux, released installers with about 20 selections each tested these
paths. A v1.2.0, v1.1.0 or v1.0.1 install then one **Update tools** with this
release ended with Check ready. A v1.0.0 install stopped before any change with
the v1.2.0 step. After **Update tools** with v1.2.0, it updated to this release,
and one **Choose tools** run released the old Sentinel records. The macOS and
Windows updates are not tested.
