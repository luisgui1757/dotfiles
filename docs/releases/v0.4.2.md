# v0.4.2 — User-owned npm globals under Nix

> Release candidate notes. Publish these only with the official annotated
> `v0.4.2` tag after the deterministic evidence gate below passes.

## Highlights

- POSIX keeps one canonical Node/npm runtime owned by Nix while giving npm a
  writable user-global package plane under `~/.local`. Normal setup persists
  that prefix through npm's own user-config writer, preserves unrelated
  registry/auth settings, and fails closed unless `npm prefix --global` reads
  back exactly `~/.local`.
- After upgrading through the normal setup entry point, personal CLI installs
  such as `npm install --global @openai/codex` work without `sudo` and without
  trying to mutate `/nix/store`. One-off packages remain available through
  `npm exec --package <package> -- <command>`.
- Native Windows setup no longer attempts to replace the PowerShell 7
  executable that is hosting it. Ordinary `-All` reconciliation keeps an
  existing `pwsh`; an explicit `-Update` must run under Windows PowerShell 5.1
  and fails before mutation when invoked from active PowerShell 7.

## Compatibility and upgrade

This is a backward-compatible patch release. It adds one user-owned npm config
field on POSIX and tightens Windows update-host safety; it does not add a second
Node installation, move a managed dotfile, or change persisted application data
shapes.

Do not update an older checkout in place. Clone the exact annotated `v0.4.2`
tag beside the checkout that currently owns live config, then run:

```bash
./setup.sh --all
```

```powershell
.\setup.ps1 -All
```

Existing v0.2.0, v0.3.0, v0.4.0, and v0.4.1 installations use ordinary
setup reconciliation from the new checkout. The same entrypoints support a
direct side-by-side v0.1.0 migration through the versioned frozen-source
transaction. Keep the prior checkout and any printed recovery directory until
setup completes and the applications you use have been checked. An unfinished
v0.2.0, v0.3.0, v0.4.0, or v0.4.1 recovery must be accepted or rolled back
from its retained exact release checkout first; v0.4.2 setup refuses to bypass
any earlier transaction.

On POSIX, successful setup guarantees:

```bash
npm prefix --global
# /home-or-users-path/.local

npm install --global <package>
```

The exact printed prefix depends on the account home. Never add `sudo`, install
a second mutable Node runtime, or hand-replace the Nix-owned Node executable.
